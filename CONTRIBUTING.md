# Contributing

Use issues for proposals, corrections, source evidence and scope questions. State the observed reference revision, what is wrong, proposed change and acceptance evidence; do not post private repository material. Check [NOTICE.md](NOTICE.md) first: the public repository is source-available, not generally licensed for modified redistribution. The issue/PR channel does not confer blanket permission to modify or distribute the reference. Maintainer-authorized contributions only; confirm rights to submit material.

Maintainers: work on a scoped branch, update VERSION and CHANGELOG for approved checkpoints, run `python3 scripts/check_foundation.py`, use standard public GitHub-hosted CI, review exact candidate and obtain owner approval before integration. Do not add unnecessary services, installers or dependencies. Do not claim product qualification from reference tests.

Documentation corrections, diagram design, source research, accessibility reviews and verification evidence are valuable contribution types alongside code. Credit only actual contributions with permission; do not publish personal details without authorization. Preserve the [locked documentation strategy](docs/documentation-strategy.md) unless the owner approves a change.
